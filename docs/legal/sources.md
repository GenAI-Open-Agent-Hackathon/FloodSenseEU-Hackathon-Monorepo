## Notes per source

### 1. Open-Meteo
- Terms page: https://open-meteo.com/en/terms. Licence page: https://open-meteo.com/en/licence.
- Upstream GloFAS and Copernicus licences are linked from the licence page and were not read. Open: read them before we cite GloFAS values as such.
- `floodsense_seed.discharge_daily` and `floodsense_seed.hazard_timeline` also hold a frozen Ahr extract for EMSR517 (AHR01-AHR04; archive API ERA5 rain 13-16 Jul 2021, Flood API GloFAS discharge 10-20 Jul 2021), made by `ingestion/prep/ahr_hazard.py`. Same licence and attribution; covered by provenance rows `ds_open_meteo_rain` and `ds_open_meteo_flood`. Reanalysis, not gauge or station observations. These values are far below the literature: ERA5 smooths the storm (14 Jul about 45-60 mm at AHR01/AHR02/AHR04, 108 mm at AHR03 Schuld) and the GloFAS peak is 213-285 m3/s on 14 Jul against ~1000 m3/s reconstructed at Altenahr. Do not quote literature figures as values of these views.
- The terms do not address storing or caching. Open: ask info@open-meteo.com if we keep copies beyond the demo.
- `floodsense.eu_watch` (migrations 060-065, 27 Oct 2026) reads the Flood API at query time for 11 river points outside Germany (France, Italy, Spain, Poland, Austria, Hungary, Belgium, Czechia). Cell choice and the long-term mean check per point: `ingestion/feeds/README.md`. CC BY 4.0: show `Weather data by Open-Meteo.com` with a link to open-meteo.com wherever a value or band is shown (the Now page footer and map attribution do). Its band compares the 7-day forecast maximum with the point's own exact past-30-day median; it is model output, labelled "model, not an official warning" in the view (`basis`), the agents' claims and the UI. Provenance: the existing Flood API row (`ds_open_meteo_flood`). The seed twin holds positions only, no values.
- `floodsense.hazard_now` reads the forecast API (past hours and forecast hours in one rolling window) and the rolling GloFAS table. Each hour is labelled `past` or `forecast`. `past` is Open-Meteo `past_days` plus GloFAS model output, not a station measurement. The same attribution string applies. Provenance row `ds_open_meteo_forecast`. The seed twin is the frozen 28–30 Oct 2024 extract, labelled `replay`, not a present.

### 19. Open-Meteo forecast API, DWD ICON (forecast lane)
- Pages read on 27 Oct 2026: https://open-meteo.com/en/licence (API data CC BY 4.0; credit, a licence link and a link next to any place the data is shown; example text `Weather data by Open-Meteo.com`), https://open-meteo.com/en/terms (free API non-commercial only; under 10,000 calls/day, 5,000/hour, 600/minute), https://open-meteo.com/en/docs/dwd-api (ICON-D2 ~2 km, ICON-EU ~7 km, ICON global ~11 km; hourly; the page names no DWD-specific licence), https://www.dwd.de/EN/service/legal_notice/legal_notice.html (open data and HVD services under CC BY 4.0, "providing the source is acknowledged") and https://www.dwd.de/EN/service/legal_notice/templates_dwd_as_source.html ("Source: Deutscher Wetterdienst" for unaltered data; for derived data a mention such as "Based on data from Deutscher Wetterdienst").
- `floodsense.weather_forecast` (071) re-fetches one request for all 45 places at query time; nothing is stored. The agents sum it (48 h and 72 h totals, wettest hour), which is derived data, so the provenance row (073) names Open-Meteo and the DWD model, and the UI attribution is `Weather data by Open-Meteo.com, model DWD ICON`.
- Call budget: Open-Meteo counts each location of a multi-location request. The agents read the weather forecast for all asked places in one query, and every query re-fetches the 45-location table, so one forecast-lane question is about 45 calls (plus the `eu_watch` / `hazard_now` fetches) against the 10,000/day free limit (roughly 200 questions a day). The API cache (`CACHE_TTL_LIVE_S`) absorbs repeats. Open: confirm the per-location counting with Open-Meteo before any public demo.
- The seed twin (072) holds the 45 positions only, no forecast value.
- Not used: DWD warnings. Bright Sky (row 7) stays on Hold. Follow-up only: DWD's own CAP warnings are on https://opendata.dwd.de/weather/alerts/cap/ (official DWD open data, CC BY 4.0 / GeoNutzV). They come as zipped CAP XML per commune or district (for example `COMMUNEUNION_DWD_STAT/Z_CAP_C_EDZW_LATEST_PVW_STATUS_PREMIUMDWD_COMMUNEUNION_MUL.zip`), which a Lightning REST table cannot read without an unzip step, so it is not simple. DWD also asks that an altered warning carries no DWD source details. A poller like `pegel_poll.py` that unzips to a FILESTORE CSV would be the route; not built.
