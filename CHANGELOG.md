# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Increment tags are `v0.MINOR.0` only (`v0.0.0`, `v0.1.0`, `v0.2.0`, `v0.3.0`, `v0.9.0`, `v0.12.0`, `v0.13.0`, `v0.14.0`). There is no `v0.MINOR.PATCH` tag and no `v0.x.y` fix tag. A fix on the 0.x line is included in the next minor tag. `v0.4.0` through `v0.8.0` are not tags; those increments shipped inside `v0.2.0`. `v0.10.0` shipped inside `v0.2.0`. `v0.11.0` is the retired name for layer (c) and is not a tag. `v0.13.0` is the demo baseline. `v0.14.0` is RAG layer (c), with `FF_RAG_DOCS` still off. There is no patch ladder between `v0.9.0` and `v0.14.0`. The Monday freeze remains `v1.0.0-rc.1`. Tags are annotated and are not moved or deleted. The GitHub wiki is disabled. Notes for a tag are this file and the GitHub Release. The steps are in [docs/RELEASING.md](docs/RELEASING.md).

### Added

- Submission docs: `docs/SUBMISSION.md` evaluation results (Anthropic test-provider full set of 21 items and a Nightshift / Nemotron Lightning subset), with reports in `docs/evals/`. `docs/architecture/c4.md` and `docs/GAMEPLAN.md` now say Lightning answers both Nightshift lanes, as measured on 27 Oct.
- Nightshift fit: Nemotron now answers the Investigator, the Playbook, the Skeptic and the Judge on a normal EMSR773 run (with doc_query), where before the Investigator and the first Playbook call fell back to the deterministic path. Nightshift's ~45 s cut comes from Meterless (`provider_deadline`, `empty_response`), not from prompt size: a skeptic prompt of 900 characters hit it too, because hidden reasoning runs 1,300 to 5,500 completion tokens. Calls are now **streamed** (`LLM_STREAM`, on by default) and assembled into the same reply shape. That lets most long generations finish (measured up to 131 s). A stream that ends in a provider error gets one more try. The Investigator rewords the deterministic chain with **one small call per link** (rain->catchment, catchment->river, river->site), in parallel. Each call carries only that link's draft claims and cited rows (compact, at most 8 rows, rows holding the claimed numbers first, short query aliases Q1..). Results merge in link order, claims are renumbered C1.., and a link whose call fails keeps its deterministic claims. #65's empty-evidence drop and `cited_numbers` apply to each link's claims. The Playbook prompt sends exposure totals and the 5 largest sites in place of the full asset list (4,980 -> about 3,000 characters), with at most 4 actions. The run-level `model_ids` (run body and approval payload) is read from the trace: every model that answered any node (Skeptic, Judge and repair included), once each and in node order, without "deterministic". `scripts/bench_nightshift.py` takes `--doc-query` and prints each node's model_id.

- `evals/run_evals.py --provider <name>` runs every item on one LLM provider (default: the deployment default, Nightshift), and `--items id1,id2` runs only those items. The report header names the provider.

- Nightshift speed: one full EMSR773 run on Nightshift drops from 864 s to 225 s (investigator 147.5 -> 51.5 s, skeptic 315.8 + 155.0 -> 46.9 + 49.5 s, playbook 144.2 -> 38.4 s, judge 97.0 -> 30.6 s). Root cause: the Nightshift gateway answers 502 at about 45 s on long generations, and the client retried that 3 times (about 144 s) before the node fell back; the 180 s timeout was never hit. An error after `LLM_SLOW_FAIL_S` (20 s) or a timeout is no longer retried, other errors get `LLM_MAX_ATTEMPTS` (2) tries, and `LLM_MAX_TOKENS_FAST/DEEP` cap runaway replies. Skeptic rationales and Judge grounding calls run concurrently (`LLM_MAX_PARALLEL`, 6) with results in input order. **Behaviour change:** with the default `JUDGE_REPAIR_WHEN_PASSING=false`, a run that passes the Judge but still has flagged claims goes to the human without a repair round; the flags stay visible. Set it to `true` for the old routing. A reply cut at `max_tokens` (`finish_reason: length`) is an error, not retried, so the node falls back. A 429 honours `Retry-After` (capped at 10 s). `scripts/bench_nightshift.py` measures one run per node and per call.

### Added

- `retrieve_docs` ranks paragraph chunks in Postgres and hydrates the passage through Zetaris when `FF_RAG_DOCS` is on. The Investigator calls it once when the request sets `doc_query`. The Judge requires a layer (c) quote to be a substring of the cited passage, and a layer (c) citation alone does not pass ([#45](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/45)). `FF_RAG_DOCS` stays off.
- NIM embeddings client for `nvidia/llama-nemotron-embed-1b-v2`, since replaced by `nvidia/nemotron-3.5-embed-1b` (see Fixed) ([#44](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/44), 2048 dimensions, `input_type` `passage` or `query`). `scripts/rag_ingest.py` writes paragraph vectors into `rag.chunks` and caches them under `corpus/.embed-cache/`. A section-only paragraph uses the section index as `page` so `page` stays at least 1.
- `rag.chunks` table and halfvec HNSW index in `pgvector/migrations/001_rag_chunks.sql` ([#43](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/43)). Zetaris JDBC registration is `zetaris/migrations/044_register_pgvector_rag_chunks.sql`, with the password left as `${PGVECTOR_PASSWORD}`. The migration creates no rows.
- Layer (c) corpus manifest and redistributable Tier 1 and Tier 2 copies under `corpus/` ([#42](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/42); EMSR773 Horta Sud delineation map, EMSR517 Bad Neuenahr-Ahrweiler grading map, the HESS and NHESS papers, and the EasyxLab S19 paper snapshot). `python tasks.py fetch-rag-corpus` checks sha256 and downloads `placement: fetch` files into `corpus/fetched/`. It does not embed and it does not start Docker. Licences for EMSR517, the two papers, and EasyxLab S19 are in `docs/legal/sources.md`.
- Layer (c) tool-RAG design ([#41](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/41)). `v0.11.0` is the retired name and is not a tag. Spec: `docs/superpowers/specs/2026-10-26-rag-layer-c-design.md`. The citation schema requires `quote`, `query_id`, and `locator.page`, `locator.paragraph`, and `locator.lines` when `layer` is `c`, and adds optional `chunk_id`. Every citable layer (c) paragraph sets `locator.page` ≥ 1. A source with no PDF pagination still uses a page-like id (`1` for the whole document, or one id per section). `page` is never null, and `section` does not replace it. Layers `a` and `b` stay valid without those fields. ADR 0009 records the embedding model (`nvidia/llama-nemotron-embed-1b-v2`, dimension 2048, NVIDIA NIM). Chat stays on Nightshift. Document embeddings are the ADR 0009 exception.
- API rate limits (`api/app/ratelimit.py`). `POST /runs` has a per-client token bucket (`RATE_LIMIT_RUNS_PER_MIN`, 10); approval is not limited. Live runs in flight to the agents are capped (`RATE_LIMIT_MAX_CONCURRENT_RUNS`, 2); a cache hit takes no slot and, with `FF_CACHED_REPLAY` on, a full cap serves the labelled replay. A refusal is HTTP 429 with `Retry-After`. GET routes are not limited.

### Fixed

- Layer (c) embeddings use `nvidia/nemotron-3.5-embed-1b`. NVIDIA NIM retired `nvidia/llama-nemotron-embed-1b-v2` on 2026-08-25 and answers it with HTTP 410, so `rag_ingest` could not embed. The new model takes the same request at 2048 dimensions. `pgvector/migrations/002_rag_embed_model_nemotron35.sql` moves the `rag_chunks_embed_model` check. `FF_RAG_DOCS` stays off by default.
- `RunRequest` keeps `doc_query`. The field was missing, so pydantic dropped it and a run through `POST /runs` never reached `retrieve_docs` even with `FF_RAG_DOCS` on.
- The agents image installs `psycopg[binary]`. `python:3.12-slim` has no libpq, so `retrieve_docs` failed with `no pq wrapper available`.
- `retrieve_docs` accepts `page` and `paragraph` as digit strings. Zetaris REST hydrates every column as a string, so every live layer (c) passage was dropped and a run had no layer (c) citation ([#51](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/51)).
- pgvector search binds the query vector and the event id on every reuse in the halfvec statement and the exact fallback. The Judge matches each layer (c) quote to its own passage when one hydrate returns several chunks under one query id ([#45](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/45)).
- `rag.chunks` checks reject a null `embed_model` on a row that has an embedding, and a null `page` or `paragraph` on a paragraph row. A comparison with null is unknown, and a `CHECK` allows unknown ([#43](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/43)).
- The EasyxLab S19 snapshot omits the Cloudflare challenge script and Web Analytics beacon that the host appended after the footer ([#42](https://github.com/GenAI-Open-Agent-Hackathon/Hackathon-Monorepo/pull/42)). `.gitleaksignore` names that beacon on commit `934bd03` only. The current file has no beacon.

- `tasks.py`, a standard-library task runner: `init-env`, `check-env`, `up`, `up-all`, `down`, `config`, `zetaris-sync`, `test`, and `lint`. `init-env` copies each missing `.env.example` to `.env` and does not overwrite. There is no Makefile.
- Placeholders. The API implements `GET /health` only. `python -m floodsense_agents` serves a JSON health check on port 8100, and `build_graph()` raises `NotImplementedError`. The UI is a Vite, React, and TypeScript placeholder and does not call the API. `scripts/zetaris_sync.py` prints a TODO, exits 0, and applies no SQL. `zetaris/migrations/` has no SQL files yet. `agents/`, `api/`, and `ui/` do not import `contracts/`.
- Env examples that are safe to commit. Filled `.env` files are gitignored. Host examples use `127.0.0.1`. The agent container example uses `host.docker.internal`.
- Shared contracts in `contracts/schemas/floodsense.schema.json` (JSON Schema draft 2020-12) for `claim`, `citation`, `evidence`, `answer`, `playbook_action`, `approval`, and `judge`. Pydantic and TypeScript are hand-checked mirrors, not generated code. Files in `contracts/examples/` are fixtures, not measurements. `python tasks.py test` validates those examples against the schema and the Pydantic models. Direct test dependencies are pinned to pydantic 2.14.1 and jsonschema 4.26.0. Wire names are snake_case.
- `python tasks.py lint` rejects a tracked `.env` other than an example, runs Ruff, and typechecks `ui/` and `contracts/`. Gitleaks runs when the binary is on `PATH`.
- GitHub Actions workflow `.github/workflows/ci.yml` on pull requests to `main` and on pushes to `main`. The job uses `ubuntu-latest`, installs gitleaks 8.30.1 from the release archive after a checksum check, sets up Python 3.12 and Node 20, then runs `python tasks.py lint` and `python tasks.py test`. `FLOODSENSE_REQUIRE_GITLEAKS=1` fails the job when the scanner is missing. The workflow does not use Docker and does not call Zetaris or Nightshift. There is no pre-commit hook.
- C4 system context, container, and agent diagrams in `docs/architecture/c4.md` (Mermaid). A box is the gameplan unless the caption says that service is in `compose.yaml` today.
- ADR 0001 (Accepted): decisions are recorded in `docs/adr/`. ADRs 0002–0008 are Proposed, not accepted: one repository with owned folders, Zetaris as the only data path for agents, Nightshift as the only path for model calls, human approval before any outbound action, labelled cache and replay, JSON Schema as the shared contract, and GitHub-hosted CI.

### Security

- `.gitleaks.toml` keeps the default gitleaks rules and adds an `nvapi-` rule. CI fails when the scanner matches, and when a filled `.env` is tracked.
- The API, UI, pgvector, and Redis ports bind to `127.0.0.1`. Redis has no password. The pgvector example password is a local placeholder.
- Examples contain placeholders, not tokens. The NVIDIA provider key is not an application variable.
