## [1.0.1] - 2026-10-27

**Highlights.** A cleanup of 1.0.0 before submission. No new features. The test-only alternative LLM provider switch is gone, answers no longer show a hallucination percentage, and the docs describe the Nightshift lanes without naming a model per lane.

### Removed

- The test-only alternative LLM provider switch, end to end: the agents' provider client and router, `LLM_PROVIDER_SWITCH` and its keys in `agents/.env.example`, the `llm_provider` field of `POST /runs`, `llm_providers` in `GET /config` and `GET /system`, the provider part of the API cache and replay keys, the operator console and desk header select, `evals/run_evals.py --provider`, and the tests and the eval report that only existed for it. Every model call goes to Nightshift.
- Hallucination percentages on the product surface: the Checked line under an answer, the Review "How this answer was made" line, the operator console Judge panel, and the committed eval reports (`docs/evals/`). `evals/run_evals.py` still computes the rate for its `--strict` target and the JSON, but no longer prints it in the report or the console.

### Changed

- Docs say what the lanes use: both lanes use Nemotron models chosen by Nightshift (Lightning 30B A3B answered every call recorded on 27 Oct). Answers are described as cited and judged, with no rate quoted.

## [1.0.0] - 2026-10-27

**Highlights.** FloodSense EU 1.0.0 is the version we submit to the Open Agent Hackathon 2026 (Track 02). It explains why a place in Europe is at flood risk, and every sentence cites a Zetaris query, a stored document passage or an approved memory.
Three desks share one console: Citizen, Insurer, and Civil protection (the operator desk, with a Situation board and a call script for hotline staff).
A router sends each message to a lane: `reply` (front door), `quick` (live reading), `forecast` (next 48 h or this week) or `full` (the multi-agent run). The first three build their answers from data and fixed templates, without a model (only an ambiguous message may use one short classification call), and answer in about 1 to 4 seconds.
The full lane runs Scope, Watchers, Memory, Investigator and Skeptic, Exposure, Playbook and a deterministic Judge, then waits for a human. It takes 5 to 6 minutes on Nemotron through Nightshift.
The Control tower is a rule-based watch loop over 45 sources (26 PEGELONLINE gauges, 11 GloFAS points, 8 Valencia demo points). It makes no model calls; an opt-in, capped auto-assess can start a full run but never approves anything.
Data comes only through Zetaris views. Forecasts use DWD ICON via Open-Meteo. The document corpus has 25 documents and 1,859 passages, including 13 pinned Wikipedia snapshots on past river floods.
Memory is written only after a human approves. Approved live runs are recalled in later answers, and 59 cited demo-seed memories are always labelled as seeds.
The UI has a global Live | Past flood switch and a Demo data switch, a "How this answer was made" panel for each sponsor technology, and a views cache that serves the last good data when Open-Meteo rate-limits.
Engineering: every change went through a branch, an independent review and a pull request; Nightshift calls back off on NVIDIA 429 errors; a poller container keeps the German gauges fresh.
Honest limits are listed in the README and in docs/RELEASE-NOTES-v1.0.0.md: modelled river data is not an official warning, the insurer portfolio is synthetic, and answers are in English only.

It reads the root `.env` (`127.0.0.1`), confirms that `/models` lists `MODEL_FAST` and `MODEL_DEEP` (an unlisted composed `meterless/` routing mode is a warning, not a failure), sends one JSON chat completion per tier with the agents client's request body (temperature 0.1, thinking off, JSON mode with the same 400 fallback; only the check caps the reply, at 256 tokens), and checks that each tier is answered by the model it wants (`EXPECT_MODEL_FAST` and `EXPECT_MODEL_DEEP`, both `nvidia/nemotron-3.5-super-vl-120b-a12b` by default; `any` accepts any model). A reply from another model is a warning, and so is both tiers answered by one model when they want different ones. `--probe` sends each candidate model id up to three times (`--probe-rounds`), shows which model answered, suggests `MODEL_FAST` and `MODEL_DEEP` values that reached the wanted model every time, and lists any routing details Nightshift returns beyond the model name. It skips local, fusion, cluster, embedding and media modes, so it never starts a local model load, and an upstream 5xx does not end a probe. The check also probes `/embeddings` when an embedding model is listed and prints a markdown summary for pull requests. It never prints the runtime token: the token is scrubbed from every server reply before any text is cut short, and a JSON error is shown in full, including Nightshift's own detail fields. Exit 0 when no required check fails (warnings included), 1 on a failed check, 2 on a config error. Run it with `python scripts/nightshift_check.py`. Tests in `scripts/tests/test_nightshift_check.py` use a fake runtime on `127.0.0.1`.
- `engines/`, a TypeScript sidecar that runs the Meterless H-MEM and World Model reference engines (Apache-2.0, copied unchanged into `engines/vendor/` from Meterless commit `1742dec`) behind a small HTTP API for the agents. Wire names are snake_case and follow the agents' models and `contracts/` (`claim_id`, `citations[].query_id`, hypothesis `statement` with `proposed`, `supported` or `not_supported`, and the run-level `approval.status` and `reviewer`), so the agents can post their pydantic objects as they are. H-MEM stores the claims of an approved or edited run with their Zetaris `query_id`s (any other approval status writes nothing), recalls them, takes feedback, and returns the trust-ledger trace for a memory. World Model holds the hypothesis board, with status changes kept as facts that survive a restart, and ingests the Watchers' anomalies and other observations idempotently. A write is checked in full before anything is stored, and retries are safe: memories are keyed by `(run_id, claim_id)`, and an unchanged hypothesis, status or concern writes nothing. `confidence`, `top_n`, `threshold` and `limit` are range-checked. Node.js 22.18 or newer (the lint and UI job stays on Node 20; the engines job uses 22.18), no runtime dependencies: `npm start` (reads an optional `engines/.env`; see `engines/.env.example`), `npm test` (18 tests), `npm run conformance` (H-MEM 13/13, World Model 8/8). A body over 1 MB is a 413, and the connection is closed. `python tasks.py init-env` copies `engines/.env.example` too, and `npm run typecheck` needs `npm install` for its two dev dependencies (TypeScript and `@types/node`). The agents service in `compose.yaml` reaches it at `ENGINES_URL=http://engines:8300` (on the host, `http://127.0.0.1:8300`, bound to loopback). `python tasks.py engines-test` and the CI `engines` job run `npm test` and `npm run conformance` on Node.js 22.18 or newer. The lint and UI job stays on Node 20. Files under `engines/vendor/` are unchanged.

### Changed

- Investigator, Skeptic rationale, and the first Playbook draft call Nightshift on lane `fast` (`MODEL_FAST`). Judge grounding and Playbook repair stay on `deep`. While Super VL answers both lanes, that switch is not by itself a large wall-time win. It helps when `MODEL_FAST` is a cheaper or faster model, such as Lightning. `SKEPTIC_MAX_ROUNDS` stays the cap (default 3). A smoke run can set it to 1.
- Watchers, the Investigator's aggregate queries, and the Exposure join run independent Zetaris statements together, capped by `ZETARIS_MAX_PARALLEL` (default 8; `1` is one at a time). That overlap is the guaranteed gain. Result order matches the call order. A query that raises is `Evidence.error` and does not drop the others. A stale login token is cleared only when it is still the token that failed, so two concurrent 401s log in once.
- README, ownership, and the gameplan name tagged v0.0.0, v0.1.0, and v0.2.0. v0.2.0 is the live agents graph, the insurer desk, the engines sidecar, the fast lane, and parallel Zetaris reads, including the agent graph, HITL, Judge, API run proxy, and evals from #4. - `MODEL_FAST` and `MODEL_DEEP` in `.env.example` and `agents/.env.example` are now `meterless/fast` and `meterless/deep`. Nightshift model ids are routing modes, so a request that named a model was answered by whichever lane Nightshift picked: the first live run got the 30B on both tiers, later runs the 120B. ## [0.0.0] - 2026-10-23

Skeleton and guardrails on `eacf34c`. The product described in the gameplan (live answers, ingestion, human approval, the insurer console) is not in this tag.

### Added

- Repository skeleton: README, gameplan, path ownership, and the folders `ingestion/`, `zetaris/migrations/`, `agents/`, `api/`, `ui/`, `infra/`, `pgvector/`, `contracts/`, `docs/`, and `scripts/`. The skeleton review is `docs/reviews/0001-skeleton-review.md`.
- `compose.yaml` for this application only, Compose project `floodsense-app`. It does not start Zetaris. `python tasks.py up` builds the API (published on `127.0.0.1:18000`), the agent runtime (no host port), and the UI (`127.0.0.1:15173`). `up-all` also starts optional pgvector (`127.0.0.1:15432`, profile `rag`) and Redis (`127.0.0.1:16379`, profile `cache`). `tasks.py` always passes `-p floodsense-app`, `--project-directory`, and `-f compose.yaml`, so `COMPOSE_PROJECT_NAME` and `COMPOSE_FILE` cannot point the script at another project. `up` refuses to start until `api/.env`, `agents/.env`, and `ui/.env` exist. `down` stops this project only, keeps volumes, and does not need `pgvector/.env`.
- `tasks.py`, a standard-library task runner: `init-env`, `check-env`, `up`, `up-all`, `down`, `config`, `zetaris-sync`, `test`, and `lint`. `init-env` copies each missing `.env.example` to `.env` and does not overwrite. There is no Makefile.
- Placeholders. The API implements `GET /health` only. `python -m floodsense_agents` serves a JSON health check on port 8100, and `build_graph()` raises `NotImplementedError`. The UI is a Vite, React, and TypeScript placeholder and does not call the API. `scripts/zetaris_sync.py` prints a TODO, exits 0, and applies no SQL. `zetaris/migrations/` has no SQL files yet. `agents/`, `api/`, and `ui/` do not import `contracts/`.
- Env examples that are safe to commit. Filled `.env` files are gitignored. Host examples use `127.0.0.1`. The agent container example uses `host.docker.internal`.
- Shared contracts in `contracts/schemas/floodsense.schema.json` (JSON Schema draft 2020-12) for `claim`, `citation`, `evidence`, `answer`, `playbook_action`, `approval`, and `judge`. Pydantic and TypeScript are hand-checked mirrors, not generated code. Files in `contracts/examples/` are fixtures, not measurements. `python tasks.py test` validates those examples against the schema and the Pydantic models. Direct test dependencies are pinned to pydantic 2.14.1 and jsonschema 4.26.0. Wire names are snake_case.
- `python tasks.py lint` rejects a tracked `.env` other than an example, runs Ruff, and typechecks `ui/` and `contracts/`. Gitleaks runs when the binary is on `PATH`.
- GitHub Actions workflow `.github/workflows/ci.yml` on pull requests to `main` and on pushes to `main`. The job uses `ubuntu-latest`, installs gitleaks 8.30.1 from the release archive after a checksum check, sets up Python 3.12 and Node 20, then runs `python tasks.py lint` and `python tasks.py test`. `FLOODSENSE_REQUIRE_GITLEAKS=1` fails the job when the scanner is missing. The workflow does not use Docker and does not call Zetaris or Nightshift. There is no pre-commit hook.
- C4 system context, container, and agent diagrams in `docs/architecture/c4.md` (Mermaid). A box is the gameplan unless the caption says that service is in `compose.yaml` today.
- ADR 0001 (Accepted): decisions are recorded in `docs/adr/`. ADRs 0002–0008 are Proposed, not accepted: one repository with owned folders, Zetaris as the only data path for agents, Nightshift as the only path for model calls, human approval before any outbound action, labelled cache and replay, JSON Schema as the shared contract, and GitHub-hosted CI.

### Security

- `.gitleaks.toml` keeps the default gitleaks rules and adds an `nvapi-` rule. CI fails when the scanner matches, and when a filled `.env` is tracked.
- The API, UI, pgvector, and Redis ports bind to `127.0.0.1`. Redis has no password. The pgvector example password is a local placeholder.
- Examples contain placeholders, not tokens. The NVIDIA provider key is not an application variable.
